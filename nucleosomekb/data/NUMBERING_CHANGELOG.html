Numbering changelog

Generated by scripts/build_numbering_changelog.R — do not edit. Every row is computed from the committed docs/data/alignment_meta.parquet and docs/data/alignment_columns.parquet, so this file cannot fall behind the artifacts it describes.

A column index is a fact about a VERSION of the registry (CLAUDE.md §8, “Registry versioning”): the alignment, the prune threshold and the numbering are one versioned object. If you have stored aln_column values, every row below is a point at which they may have become wrong. family_position is derived from the alignment too and moves with it.

moved is the number that matters. A new aln_version is necessary but not sufficient for a coordinate to move — admitting a member re-runs the MSA and changes the hash even where every existing index survives. moved counts (uniprot_id, protein_position) pairs that landed in a DIFFERENT aln_column than in the previous version. - means the comparison was not available (the family is new, or that commit predates the shipped columns table).

Assert against alignment_meta.input_sha256 to detect staleness; see tables/SCHEMA.md § Detecting stale positions.
